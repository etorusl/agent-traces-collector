# Подключение сервера и эксплуатация

## vLLM

Агент вызывает `/v1/chat/completions` с `n=1`, `stream=false`. Протокол действий
задан текстом системного промпта. Серверному tool-calling parser не требуется
распознавать инструменты; от модели ожидается один JSON object после reasoning.
Gemma 4 также может выдавать нативный `<|tool_call>call:python{...}<tool_call|>`.
Сборщик разбирает один такой вызов, включая строковые и числовые аргументы,
и приводит его к тому же внутреннему JSON-действию. Код парсера не использует `eval`.

Для Qwen3 с thinking на стороне vLLM нужен подходящий reasoning parser. Пример
формы команды (версию сервера и checkpoint выбирает владелец сервера):

```bash
vllm serve "$SERVER_MODEL_PATH" --served-model-name "$VLLM_MODEL" --reasoning-parser qwen3
```

Официальная [документация vLLM](https://docs.vllm.ai/en/latest/features/reasoning_outputs/)
описывает поле `reasoning`; прежние версии используют `reasoning_content`.
Сборщик поддерживает оба. Имена parser и возможность thinking зависят от
**точного варианта модели**, а не только от размера «30B-A3B».

Для smoke достаточно проверить доступность `GET /v1/models` и выполнить `doctor --probe`.
Для большого эксперимента запишите в конфигурацию checkpoint commit/хеш,
tokenizer revision, dtype/quantization, vLLM version, parser, chat template и
значимые серверные параметры. Дополнительные поля допустимы внутри
`[model.server_metadata]`; они входят в experiment fingerprint.

В `[model.extra_body]` допустимы параметры vLLM, например `top_k` или
`repetition_penalty`, если они нужны выбранной модели. Они не должны подменять
контролируемые `model/messages/n/stream/max_tokens/temperature/seed`.
Все фактически отправленные тела запросов сохраняются в трассе.

## Разбор проблем

| Ситуация | Действие |
| --- | --- |
| `Unresolved environment variable` | Задать переменную в том терминале, который запускает CLI; `.env` не загружается сам |
| HF 401/403 или gated access | Проверить доступ аккаунта к GAIA, принятие условий, `HF_TOKEN`; ключ не вставлять в конфиг |
| `Missing ... metadata.parquet` | Выполнить `prepare-gaia` или указать `gaia_root` корня официального snapshot |
| Ошибка модели в `/models` | Указать точный served ID, включая алиас, и правильный URL с `/v1` |
| HTTP 400 | Проверить совместимость `chat_template_kwargs` и остальных extra_body с сервером; ошибка сохранена в трассе |
| `missing_usage` | Endpoint не вернул `completion_tokens`; сборщик останавливается, чтобы не обходить бюджет |
| Reasoning `null` | Проверить `doctor --probe`, поля сообщения, server usage breakdown; при необходимости включить отдельную tokenizer-оценку |
| Сервер прислал reasoning=0, но текст thinking есть | Нулю не доверяем: возвращается `null` с warning; проверить версию vLLM/parser |
| `model_length` | Модель исчерпала бюджет одной генерации; увеличить `model.max_tokens` в **новом** эксперименте |
| `protocol_error` | Модель не соблюдает JSON-протокол; посмотреть raw response, проверить parser/промпт/лимит reasoning |
| Context length exceeded | Полная история не обрезается скрыто; уменьшить лимит наблюдений/шагов или изменить context сервера в новом эксперименте |
| `tool_timeout` | Процесс инструмента убит, его Python namespace потерян; попытка считается прерванной |
| Ошибки AppWorld CLI с Click | Использовать lock-файл и подготовленную `.venv`; в релизе 0.1.3 нужен `click<8.2` |
| Resume rejected | Сравнить manifest и текущие код/настройки/данные/зависимости; для изменённого эксперимента выбрать новый output |
| Пустая стандартная выгрузка GAIA test | Скрытые ответы не позволяют подтвердить успех; для диагностики `--include-unsolved`, для успешных меток — validation |

## Ограничения исполнения

Таймауты HTTP измеряются реальным wall clock через POSIX `setitimer`, включая
медленно поступающий ответ. Инструменты и AppWorld работают в отдельных
процессах, которые родитель может принудительно остановить. Сборщик
предназначен для главного потока Linux/macOS; Windows не поддерживается.

По умолчанию запрос модели получает 4096 generated tokens, задача —
60000 generated tokens и 40 шагов; после инициализации доступно 1800 секунд.
Время setup и evaluation ограничено отдельно. Лимиты менять можно, но они
являются частью фиксированной конфигурации эксперимента.

В историю следующего запроса передаётся ответ после отделения reasoning и
результат инструмента. Reasoning не возвращается в историю; в сырой трассе
он сохраняется. Текст наблюдения ограничен `max_observation_chars`.
Длинные инструментальные результаты в трассе ограничены 200000 символов;
есть отметка усечения. Для больших файлов агент читает фрагменты или использует Python.

Тела запросов и ответов логируются, заголовок Authorization — нет. Известные
ключи окружения редактируются в событиях и итогах; ключи модели/HF также
убираются из окружения инструментального процесса. Это не изоляция от файлов
хоста: Python остаётся локальным исполнением. Не размещайте секреты в текстах
заданий, server_metadata или extra_body.

## Проверенная область

Тесты проверяют общий и раздельный учёт токенов, старый/новый reasoning API,
ошибки протокола, бюджет, HTTP timeout, ретраи с неизвестным расходом,
принудительную остановку Python, восстановление оборванного JSONL, неизменность
конфигурации при resume, отсутствие скрытых features, настоящий Parquet,
сквозной запуск CLI через локальный HTTP-сервер и штатный evaluator AppWorld.

Принятие условий GAIA, реальный checkpoint на сервере, его производительность
и точность reasoning breakdown проверяются при подключении настоящего endpoint.
Синтетические тесты не выдаются за реальные агентские трассы бенчмарков.
